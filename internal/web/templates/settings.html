What do these rules do?
stale_days
Days a PR can sit after your changes-requested review with no reply or push from the author before it moves to Stale changes requested, so you can nudge the author or close it. Default 7.
test_approval
Only for repositories where CI on pull requests from forks waits for a maintainer. Leave it as {} otherwise; workflow runs that GitHub holds for approval are detected either way.
marker_checks
Check names that only appear once tests were approved. A fork PR whose latest commit has none of them is listed under Waiting test approval.
command
The comment that approves tests, suggested as the action, for example /ok-to-test.
ci_paths
Path prefixes that deserve extra care, such as .github/. When a PR changes one, or its file list can't be read, ci_paths_command is suggested instead.
ci_paths_command
The approval comment to suggest when CI files change.

Example:

{
  "test_approval": {
    "marker_checks": ["tests / Test", "tests-skip"],
    "command": "/ok-to-test",
    "ci_paths": [".github/"],
    "ci_paths_command": "/ok-to-test confirm-ci"
  },
  "stale_days": 7
}

Saving a change to test_approval re-reads every open PR in the repository; changing only stale_days re-sorts the queue without GitHub calls.
